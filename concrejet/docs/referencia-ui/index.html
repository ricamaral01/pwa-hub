As regras que estes mockups codificam

  • Uma paleta, duas densidades. Tablet: alvo de 56 px, fonte de 15 px, valores de 26 px. Desktop: alvo de 34 px, fonte de 14 px, tabela de verdade. Os tokens são os mesmos — o que muda é --toque e a escala tipográfica.
  • Cor é sinalização, não decoração. Verde, amarelo, vermelho e azul seguem a ISO 3864, a mesma convenção que já está pintada nas máquinas. Nenhuma cor aparece sem significar estado.
  • Todo número é tabular. A classe .num usa monoespaçada com tabular-nums, para que a coluna de valores não dance enquanto o operador digita.
  • Nenhuma fonte externa. O tablet opera offline em galpão. Webfont é ponto de falha sem contrapartida.
  • No tablet não existe <select>, teclado nativo, rolagem vertical ou layout retrato. Lista curta vira grade de blocos.
  • Campo calculado nunca é editável. Na faixa de resultado não há caixa de entrada — só leitura, em tipografia maior que a dos campos digitados.

Para o Codex

Estes arquivos são especificação visual, não código de produção. Eles são HTML estático, sem estado e sem interação. O que deve ser preservado na refatoração é a estrutura de layout, a escala de tamanhos, os tokens de estilo.css e os nomes de classe. O que deve ser substituído é tudo que é conteúdo: os valores são de exemplo e existem para provar que o layout aguenta o dado real — inclusive o caso ruim, como 23.696 peças e perda de 24,3%.

Os números do apontamento batem com o exemplo de conferência do prompt mestre: 618 peças boas, 19 de refugo, peso de 0,1522 kg, borra 7,085, galho 2,315 e falha 1,135 resultam em 94,06 kg de injeção útil, 13,43 kg de perda total, 107,49 kg de injeção mais perdas e 10,56% de perda sem galho. Se a implementação não reproduzir esses valores, a fórmula está errada.
