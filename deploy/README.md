# Operação da Dosagem v2

Arquivos exclusivos da aplicação `concretrack-dosagem`. O reconhecimento real da VPS está em `docs/dosagem-v2/VPS-RECONHECIMENTO.md`. **Não execute provisionamento sem reconhecer o servidor e configurar acesso por chave, DNS e `.env` privado.**

1. Na VPS, criar `/opt/concretrack-dosagem/shared/.env` a partir de `dosagem-concreto-v2/api/.env.example`, com `chmod 600`. `DATABASE_URL` deve apontar para o banco local `concretrack_dosagem`, usuário `dosagem_app`, com senha real. Configurar `ADMIN_EMAIL`, Supabase URL/anon key do Hub ou JWT HS256/audience conforme o provedor real. Não versionar o arquivo.
2. Reconhecer SO, recursos, PostgreSQL, servidor web, portas e DNS usando o documento acima. Copiar `dosagem-concreto-v2/api` e `deploy` para um diretório temporário da VPS. Como root: `bash deploy/scripts/provisionar.sh "$PWD"`. O script exige `.env` previamente criado, instala PostgreSQL apenas se ausente, cria role/banco, usuário de sistema, nginx e unidades próprias, testa nginx antes de recarregar.
3. Depois de corrigir a divergência golden C40, no Windows, da raiz do repositório: `powershell -ExecutionPolicy Bypass -File .\deploy\scripts\deploy.ps1`. No Linux: `bash deploy/scripts/deploy.sh`. Ambos testam localmente, empacotam, enviam por `vps-antiga`, instalam release, migram banco, trocam `current`, verificam saúde e restauram release anterior se a verificação falhar.
4. Quando o DNS apontar para a VPS, emitir somente o certificado da API: `certbot certonly --webroot -w /var/www/concretrack-dosagem-acme -d api-dosagem.concretrack.com.br`. Em seguida, gerar o site HTTPS: `sed "s/__PORTA__/18300/g" deploy/nginx/api-dosagem.https.conf > /etc/nginx/sites-available/api-dosagem.concretrack.com.br.conf` (substituir 18300 pela `PORTA` real do `.env`), `nginx -t && systemctl reload nginx`. O bloco HTTP mantém o desafio e redireciona para HTTPS. Não usar `certbot --nginx`.
5. Verificar `curl -fsS https://api-dosagem.concretrack.com.br/api/v1/saude`, `systemctl status concretrack-dosagem-api concretrack-dosagem-backup.timer`, um backup manual `systemctl start concretrack-dosagem-backup.service`, e restaurar o dump em um banco temporário próprio para testar recuperação. Comparar códigos HTTP dos outros sites anotados no reconhecimento.

Rollback manual: como root, `bash /opt/concretrack-dosagem/current/deploy/scripts/rollback.sh`. Os scripts nunca reiniciam os serviços PCP, Mapa ou GED, nem o nginx; somente recarregam sua configuração depois de `nginx -t`.
