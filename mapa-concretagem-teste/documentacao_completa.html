Visão Geral

O Mapa de Concretagem é uma aplicação web PWA integrada ao cockpit de controle da fábrica. Sua função é monitorar e gerenciar em tempo real o ciclo de concretagem dos postes de concreto. A ferramenta permite o planejamento diário de moldes (formas), a liberação rápida para preenchimento com concreto, o apontamento de anomalias (defeitos de qualidade) e o controle operacional por setores produtivos.

i
Simplificação do Workspace: Todos os scripts temporários, rascunhos de homologação e tabelas legadas redundantes foram removidos da estrutura do projeto. As lógicas de sincronização offline, modelagem de dados e regras de negócio foram centralizadas e consolidadas nos arquivos oficiais (app.js, server.js, sw.js).

Arquitetura & Fluxo de Dados

A aplicação utiliza uma infraestrutura híbrida composta por cliente local offline, banco de dados em nuvem, servidor SFTP de arquivos de imagem e APIs do ecossistema Google Workspace:

P
PWA (Frontend)
Desenvolvido em Vanilla JS, CSS e HTML. Armazena dados de forma resiliente localmente no IndexedDB e LocalStorage. Continua operando mesmo sem conexão com a internet.
S
Supabase (DB)
Banco de dados relacional PostgreSQL hospedado na nuvem. Oferece consultas em tempo real, sincronização via conexões HTTP REST e segurança integrada baseada em RLS.
V
Servidor VPS (API)
Serviço Node.js/Express hospedado na VPS. Recebe uploads de fotos da auditoria de postes, processa e comprime as imagens (Sharp) e transfere os arquivos via SFTP para o storage persistente.
G
Google Sheets (Macro)
Integração secundária via Google Apps Script (GAS) para alimentar planilhas corporativas legadas e obter sincronizações em massa.

Biblioteca de APIs & Endpoints

O ecossistema divide-se entre as APIs executadas na VPS (Node.js/Express) e as integrações via Macros do Google Apps Script:

POST /api/inspecoes/:poste_id/fotos
Comprime a imagem enviada (Sharp, limite de largura de 1600px, 80% qualidade JPEG), realiza a transferência persistente por SFTP para a VPS física, e salva os metadados do upload no Supabase.
Form Data: foto (Arquivo binário/Imagem), usuario (String)
Retorno (201 Created): JSON contendo o metadado gravado na tabela fotos_inspecao.
Exemplo de resposta de sucesso
{
  "success": true,
  "data": {
    "id": "e302521c-a115-46bb-be1f-508b98132924",
    "poste_id": "2026-06-25_Setor 1_05",
    "arquivo_nome": "f8a92f03-68d1-419b-abeb-f32742911244.jpg",
    "arquivo_path": "inspecoes/2026/06/25/2026-06-25_Setor 1_05/f8a92f03-68d1-419b-abeb-f32742911244.jpg",
    "tamanho_bytes": 142095,
    "usuario": "inspetor.lima",
    "data_upload": "2026-06-25T14:23:10.000Z"
  }
}
GET /api/inspecoes/:poste_id/fotos
Recupera a lista de fotos salvas de determinado poste e monta as URLs completas HTTP apontando para o servidor web da VPS física de storage.
Parâmetros de URL: poste_id (String)
Retorno (200 OK): Lista com os metadados e as URLs públicas.
DELETE /api/fotos/:id
Remove fisicamente a foto armazenada no storage da VPS via SFTP e em seguida apaga o registro de metadados correspondente no Supabase.
Parâmetros de URL: id (UUID correspondente ao ID da foto)
Retorno (200 OK): Confirmação de exclusão do arquivo e dos registros.

Abaixo estão os endpoints utilizados na integração de dados legados do Google Sheets, expostos a partir do Web App unificado do Apps Script corporativo:

POST / GET https://script.google.com/macros/s/.../exec
Parâmetro de Ação: action enviado no corpo ou URL. Valores aceitos:
  • get_data: Retorna todos os registros agregados de massadas e produção de concretagem salvos na planilha mestra de controle.
  • listar_usuarios: Retorna a listagem de usuários válidos cadastrados no painel administrativo do Google Sheets.
  • listar_inspecao_pendentes: Retorna formas concretadas e que ainda não passaram pelo crivo da montagem/inspeção de cura.
  • salvar_inspecao_lote: Envia um lote de inspeções executadas em lote offline para atualizar a planilha do Google Drive.

Biblioteca Frontend (app.js)

O arquivo principal app.js foi desenvolvido para ser extremamente modular, resiliente à perda de sinal de rede e integrado com a renderização de telas e sincronização.

readDb() IndexedDB / LocalStorage
Executa a leitura da base local. O PWA tenta ler os dados diretamente do IndexedDB e, caso não haja suporte ou retorne erro, faz o fallback silencioso para o LocalStorage, retornando a estrutura padrão de registros.
Retorno: Objeto JSON com coleções locais estruturadas de records, users, pendingSyncs e metadata.
saveDb(data) Persistência Local
Grava a estrutura completa de dados em IndexedDB com fallback automático para LocalStorage. Atualiza a flag interna de modificação para controle de concorrência.
Argumentos: data (Objeto contendo a base inteira a ser persistida localmente).
getRowsForDashboard(data, setor) Supabase Sync
Tenta buscar em tempo real os dados consolidados da tabela producao no Supabase para preencher o grid visual do dia correspondente ao setor. Caso o cliente esteja em modo offline, aciona o fallback local getRowsFromLocalForDashboard() sem interromper a interface do usuário.
Argumentos: data (String no formato YYYY-MM-DD), setor (String correspondente ao setor produtivo).
syncOfflineData() Sincronizador
Função disparada automaticamente quando a conexão é restabelecida. Lê a fila de operações pendentes salvas em IndexedDB (pendingSyncs) e dispara requisições de gravação (upsert ou insert) para as tabelas correspondentes no Supabase. Remove as tarefas executadas com sucesso da fila.
renderGrid() Interface Dinâmica
Redesenha a matriz de formas físicas baseando-se no estado atual da programação do PCP, do tipo de concreto apontado na tabela producao e dos checklists de qualidade preenchidos. Aplica estilos HSL condicionados de forma a alertar anomalias visuais (ex: formas em vermelho indicam concreto exsudado ou segregado).

Service Worker & Comportamento Offline

O arquivo sw.js registra e controla as políticas de caching estático e as exceções operacionais de rede:

Políticas de Rede no Service Worker (sw.js)
// Pular requisições de API e Supabase (devem sempre tentar rede em tempo real)
if (url.href.includes("script.google.com") || url.href.includes("supabase.co")) {
  return;
}

// Para arquivos estáticos (HTML, CSS, JS, manifest), usa cache com fallback para rede
event.respondWith(
  caches.match(event.request).then((cachedResponse) => {
    if (cachedResponse) return cachedResponse;
    return fetch(event.request);
  })
);

Como os dados são persistidos localmente?

O PWA utiliza uma fila do tipo Log de Gravação (Write-Ahead Log) armazenada em IndexedDB/LocalStorage sob a chave pendingSyncs. Toda ação de gravação feita offline (como liberar uma forma, salvar uma inspeção ou registrar um novo tipo de concreto) gera um objeto operacional no formato abaixo:

Estrutura de Fila de Sincronização Pendente

  "action": "salvar_forma_click",
  "timestamp": "2026-06-25T14:23:30.982Z",

    "modelo": "C",
